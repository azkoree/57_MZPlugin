# 2026-09-13

## 需修复/ 目录：13 个插件「文件名已改、内部自引用未改」的统一改造

**背景**：`需修复/` 下的 13 个插件是由 GF 内置插件改名而来（如 `GF_3_AlchemySystem.js` → `WSQ_AlchemySystem.js`），
但代码内 `Imported.GF_3_AlchemySystem = true;` 等自声明未同步。

**采用方案（经用户确认）**：新名 + 旧名兼容别名。
- 自声明改为 `Imported.<新文件名> = true;`，紧接一行 `Imported.<旧名> = true; // 兼容别名（旧引用保留）`
- 文件头署名行、alert 报错文案、console.warn 前缀、@help 注释示例、`@orderAfter` 元数据、硬编码 `PluginManager.parameters('旧名')` 全部换成新名
- `GF_XXX_需求文档.md` 这类**文档文件名**保持不动（用户明确排除）

**改后小抄**：

| WSQ_CallEnemy.js | GF_4_CallEnemy |

**关键风险点（已记录）**：`GF_2_CoreOfMainMenu` 等**其它插件参数**里写着
`return Imported.GF_3_AlchemySystem;`（合成按钮显示条件）——这类外部引用靠兼容别名兜住。
同理 `GF_2_CoreOfMainMenu` 的图鉴按钮引用 `Imported.GF_3_ExternalGlossary`。

`GF_3_ToastSystem` / `GF_3_QuestSystem` / `GF_3_IndependEquipSystem`。

**产物**：原文件备份在 `需修复/_bak/`；13 个文件全部通过 `node --check`。
